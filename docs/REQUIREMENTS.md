# fuel-log 要件定義書

作成日: 2026-09-17 / 対象: ChatGPT（Codex等）による実装 / 利用者: 開発者本人のみ
リポジトリ名: `fuel-log` / 公開URL: `https://akihirokunii.github.io/fuel-log/`

> 3案のうち最も小さい。**共通テンプレート（全体方針書 §2）の検証を兼ねて最初に実装する**。本書だけで実装が完結するよう、細部まで決めてある。迷ったら §9。

## 0. 目的（本人の言葉の要約）

満タン法で算出した燃費を給油のたびに記録し、自分の車の燃費の時系列推移を見る。入力は日付・走行距離・リッター数の3つ（＋給油金額）。裏側で燃費を自動算出し、横軸日付・縦軸燃費のグラフを、株価チャートのように 1か月／半年／1年／全期間 で切り替えて見る。シンプルに、スマホ上で運用する。

**満タン法**: 満タン給油時に走行距離モニター（トリップメーター）をリセットし、次回給油時の走行距離と給油リッター数から、給油間の平均燃費を求める。

## 1. 確定事項（変更不可）

| 表示範囲 | 1か月 / 半年 / 1年 / 全期間（この4つ。既定は全期間） |
| 言語 | 日本語 |
| LLM | 使わない |

## 2. 技術スタック（固定）

React 19 + TypeScript strict + Vite / Dexie.js + dexie-react-hooks / Recharts / vite-plugin-pwa / Vitest + fake-indexeddb。
`base: '/fuel-log/'`。manifest: `name: "燃費ログ"`, `short_name: "燃費"`, `display: standalone`, `lang: ja`, `theme_color/background_color: #0b1120`。
デプロイ: push(main) → GitHub Actions → GitHub Pages（全体方針書 §2 のワークフロー）。ルーターなし。外部CDN・外部フォント・アナリティクス禁止。

## 3. データモデル（Dexie version 1）

| テーブル | 主キー / インデックス | 行の型 |
|---|---|---|
| `fillups` | `++id`, `date` | `{id?: number, date: 'YYYY-MM-DD', tripKm: number, liters: number, yen: number \| null, partial: boolean, createdAt: epochMs, updatedAt: epochMs}` |
| `settings` | `key` | `{key: string, value: unknown}`（現時点で使う設定は無し。将来用に置くだけ） |

- `partial`: 「満タンにしなかった」フラグ。既定 false。S1 の折りたたみ「詳細」内にだけ置く（通常は見えない）

## 4. 燃費の計算（純粋関数・単体テスト必須）

`fillups` を `date` 昇順（同日は `id` 昇順）に並べ、各行に派生値を付ける:

- 通常（`partial=false` で、直前の行も `partial=false` または先頭）: `kmPerL = tripKm / liters`
- **部分給油の連鎖**: `partial=true` の行は `kmPerL = null`。次に来る `partial=false` の行では、直前の連続する `partial=true` 行の `tripKm` と `liters` を自分に足し合わせてから `kmPerL` を計算する（走行距離モニターは満タン時にしかリセットしない運用のため、部分給油の行の `tripKm` は「前回満タンからの積算ではなく、その区間の距離」として入力してもらう。§9 参照）
- `yenPerL = yen / liters`（`yen` が null なら null）、`yenPerKm = yen / tripKm`（同）
- 期間統計: 対象期間の `kmPerL` が非nullの行について 平均（単純平均）・最高・最低・件数、および期間の総走行距離・総給油量・総金額（null除く）

## 5. 画面仕様

タブは3つ: **記録** / **グラフ** / **一覧**（設定は一覧タブの最下部に置く）。起動時は「記録」。

### S1 記録

1. 日付（`<input type="date">`、既定＝今日）
2. 走行距離 km（`inputmode="decimal"`、小数1桁まで）
3. 給油量 L（`inputmode="decimal"`、小数2桁まで）
4. 給油金額 円（`inputmode="numeric"`、任意。空なら null）
5. 折りたたみ「詳細」: チェック「満タンにしなかった」
6. ボタン **「保存」**。保存後は入力欄をクリアし、直下に「保存しました: 2026-09-17 / 412.3 km / 28.5 L → **14.5 km/L**（前回 13.9）」を表示。前回燃費との差を ▲/▼ で示す
7. フォームの下に直近3件（日付・km/L）。タップで S3 の編集へ

バリデーション（保存ボタン押下時、エラーは欄の下に赤字）: 走行距離 1〜2,000、給油量 0.5〜120、金額 0〜50,000（整数）、日付は今日以前。範囲外は保存しない。同じ日付の既存行があっても保存はできる（1日2回給油を許容）。

### S2 グラフ

1. 範囲切替（セグメント）: 1か月 / 半年 / 1年 / 全期間。選択は `localStorage` に記憶（既定: 全期間）
2. メイングラフ: 横軸＝日付、縦軸＝km/L。**点＋折れ線**（Recharts `LineChart`、`connectNulls: false`）。期間平均を水平の破線で描く。縦軸の範囲はデータの min−1〜max+1
3. 統計行: 平均 / 最高 / 最低 / 件数（期間内）
4. 切替で第2グラフ: 「円/L」「円/km」（`yen` がある行のみ。無ければ「金額の記録がありません」）
5. データが0件なら「記録タブから最初の給油を登録してください」

### S3 一覧・設定

1. 一覧: 新しい順。1行 = 日付 / 走行距離 / 給油量 / km/L /（金額）。部分給油は「部分」バッジ。タップで編集（S1 と同じフォームをモーダルで）。削除は編集画面内の「削除」（確認ダイアログ）
2. 設定（最下部）: **CSV書き出し**（UTF-8、ヘッダ `date,tripKm,liters,yen,partial,kmPerL`。kmPerL は派生値なので取込時は無視）、**CSV取込**（同形式。`id` は振り直し。追記）、**JSONバックアップ書き出し／復元**（全体方針書 §2 の形式、`app: "fuel-log"`、復元は置換）、保存件数、**全削除**（確認ダイアログ）

## 6. 非機能要件

- オフラインで全機能が動く（外部通信は一切ない）
- 記録の定常操作: アプリを開く → 3欄入力 → 保存（タップ・入力は合計5操作以内。日付は既定で今日）
- 純粋関数（燃費計算・期間統計・CSV入出力）は単体テスト必須
- 1,000件のデータでグラフ描画が体感1秒以内

## 7. 受け入れ条件

1. 3件の給油を登録すると、記録画面に km/L と前回差が出て、グラフ画面に3点の折れ線と平均線が描かれる
2. 部分給油（partial）を1件挟んだあと満タン給油を登録すると、部分給油の行は km/L が空欄、満タン給油の行は2区間合算の km/L になる（単体テストで境界を確認）
3. 範囲切替で1か月／半年／1年／全期間の表示が変わり、再起動後も選択が残る
4. CSV書き出し→全削除→CSV取込 で件数と値が一致する。JSONバックアップも同様
5. 実機 iPhone の Chrome でホーム画面に追加し、機内モードで 1〜4 が動く
6. `npm test` 全通過、`npm run build` が型エラーなし、GitHub Actions で公開URLに配置される

## 8. 実装フェーズ

1セッションで完了させる。順序: 雛形＋Dexie → 燃費計算（テスト）→ S1 → S2 → S3 → CSV/バックアップ → デプロイ → README（ホーム画面追加の手順を3行）。

## 9. 決定済みの細部（迷ったらここ）

- 走行距離は**トリップメーターの値（前回リセットからの距離）**を入れる。オドメーター（総走行距離）は記録しない
- 部分給油のときも、その時点のトリップ距離を入力し、**トリップメーターはリセットする**運用とする（合算計算 §4 はこの前提）。README にこの運用を1行書く
- 小数の丸め: km/L は表示・CSVとも小数1桁。円/L は小数1桁、円/km は小数2桁。内部は丸めない
- 「1か月」は今日から30日前、「半年」は182日前、「1年」は365日前、「全期間」は最古から
- 日付の昇順で並べ、同日は登録順（id）。編集で日付を変えたら並び直す
- 金額は税込の支払額。単価は入力しない（派生で算出）
- グラフの点は最大でも間引かない（1,000件程度なら Recharts で描ける）
- 色: 燃費線＝青系、平均線＝灰の破線、円系＝橙系。ダークテーマ
- 削除は物理削除（ゴミ箱は作らない）

## 10. スコープ外（明示）

- 複数車両、給油所名、燃料種別、オドメーター、メンテナンス記録、リマインダー、位置情報、外部連携

## 11. 実装時に決めたこと（実装者が追記する。「[実装判断]」を付ける）

### 燃費計算・統計（`src/core/fuel.ts`）

- [実装判断] `yenPerKm` は部分給油の連鎖を合算して算出する（`(yen 合計) / (tripKm 合計)`）。自分または連鎖のどれかの `yen` が null なら null。部分給油の行自体は null
- [実装判断] `yenPerL` は行単体で出す（満タン行でも連鎖は合算しない）。その給油の単価として意味があるため、部分給油の行でも表示する
- [実装判断] 画面の「件数」＝`PeriodStats.count`＝`kmPerL` が非 null の行数（平均・最高・最低の母数と同じ）。期間内の全行数は `fillupCount` として別に持つ
- [実装判断] 前回との差（`diffKmPerL`）は**表示値どうしの差**（小数1桁に丸めた値の差をさらに小数1桁に丸める）。画面の数字と矛盾させないため。`diff` は符号付き（悪化なら負）で、表示側が `▲`／`▼` と絶対値に分ける
- [実装判断] 派生計算は必ず全データに対して行い、期間フィルタはその後にかける（期間外の部分給油も期間内の満タン行に合算される）
- [実装判断] `previewKmPerL` の候補行は既存の最大 id + 1 の仮 id を持つ（同日の既存行より後ろに並ぶ）。`editingId` が既存データに無ければ新規として扱う
- [実装判断] 防御的に、合計給油量が0以下なら `kmPerL` は null、合計走行距離が0以下なら `yenPerKm` は null（検証を通ったデータでは起こらない）

### 表示の丸め（`src/core/format.ts`）

- [実装判断] 丸めは `toFixed` ではなく「値の最短十進表記を指数シフトしてから四捨五入」する方式（`(1.005).toFixed(2)` が `'1.00'` になる二進表現の誤差を避けるため）。負数は0から遠い側へ丸め、`-0` は `0` にする
- [実装判断] 値が無いとき（null・undefined・NaN・Infinity）の表示は全角ダッシュ `—`

### 日付（`src/core/dates.ts`）

- [実装判断] `dateToMs` / `addDays` は不正な日付文字列に対して `RangeError` を投げる（誤った数値を静かに返さない）。DB に入る日付は必ず検証を通っている

### 入力検証（`src/core/validation.ts`）

- [実装判断] 数値として受理するのは `^\d+(\.\d+)?$` の形だけ。`'412.'`・`'.5'`・`'1e3'`・`'-5'` は「数値で入力してください」。全角（NFKC 正規化）と桁区切りカンマは受理する
- [実装判断] 検証の順序は 必須 → 数値の形 → 小数桁 → 範囲（項目ごとにエラーは1件）
- [実装判断] 形式不正・実在しない日付は「日付が正しくありません（YYYY-MM-DD の実在する日付）」。フォームの日付欄では起こらず、CSV 取込のエラー表示で必須エラーと区別するための文言
- [実装判断] 金額は小数桁0として検証するので、`'4560.5'` も `'4560.0'` も「0〜50,000 円の整数で入力してください」

### CSV（`src/core/csv.ts`）

- [実装判断] CSV 取込は**全行が妥当なときだけ**取り込む（1行でも不正なら何も取り込まない）
- [実装判断] 列はヘッダ名で対応付ける（大文字小文字と列の順序は問わず、`kmPerL` など余分な列は無視）。必須5列が揃わなければ `1行目: ヘッダが正しくありません…`
- [実装判断] エラー文言は `N行目: 項目名: メッセージ`（メッセージが項目名で始まる場合は項目名を重ねない）。行番号は空行を含む元ファイルの行番号。1行に複数のエラーがあれば項目ごとに返す
- [実装判断] `partial` が `true/false/1/0/空` 以外なら `partial は true/false/1/0/空 のいずれかで入力してください`、必須列が欠けた行は `列数が足りません`
- [実装判断] 取込はダブルクォートで囲まれたフィールドも読む（Excel 等で再保存された場合への備え。書き出し側は囲まない）。フィールド内の改行には対応しない

### バックアップ・DB（`src/core/backup.ts` / `repo.ts`）

- [実装判断] `parseBackup` は型に加えて値域（入力検証と同じ範囲）と `id` の重複も検証し、未知の項目は落として正規化する
- [実装判断] 存在しない id への `updateFillup` は何もしない（例外を投げない）
- [実装判断] `appendFillups` は1トランザクションの `bulkAdd` で、入力順に id を振る

### 保存・設定（`src/core/download.ts` / `settings.ts`）

- [実装判断] iOS 判定は UA に加えて `navigator.maxTouchPoints`（iPadOS 13+ は UA が Macintosh になるため）。Web Share が `AbortError` なら `'cancelled'`、その他の失敗は `<a download>` にフォールバック。`revokeObjectURL` は60秒後
- [実装判断] `loadRange` / `saveRange` は `Pick<Storage, 'getItem' | 'setItem'>` を注入できる（既定は `globalThis.localStorage`）。参照や読み書きが例外を投げる環境でも既定値で動く

### テスト

- [実装判断] テスト用フィクスチャは `docs/samples/fillups-sample.csv` と `docs/samples/backup-sample.json`（同じ15件のデータ。部分給油1件・金額空欄2件・同日2回給油1組を含む）。`src/core/testFixtures.ts` から Vite の `?raw` で読み込む（`tsconfig.app.json` に `"types": ["node"]` が無く、TypeScript 6 は `@types/node` を自動では読まないため `node:fs` を使わない）

### 画面（グラフ、`src/features/chart/`）

- [実装判断] `ticks.ts` の `buildTimeTicks` は、細かい順に 週（月曜）→2週→月初→2か月→3か月→半年→年初→2年→5年→10年 を試し、**7本以下に収まる最も細かい刻み**を使う。幅375pxでラベルが重ならずに並ぶのが7本程度で、それを超えると Recharts が重なったラベルを間引いて間隔が不揃いになるため（記録を始めて2〜3か月目の「全期間」で実際に起きた）。14〜4000日の全期間幅で 2〜7本・範囲内に収まることを単体テストで総当たり確認
- [実装判断] `buildYTicks` は、まず 1/2/5/10 系の「切りのよい」整数刻みで4〜6本に収まるものを探し、無ければ整数刻みを1から広げて4〜6本に入る最初のもの(無理なら5本に最も近いもの)を使う。1/2/5/10 だけでは4〜6本に収まらない domain があるため(例: 11〜28 は5刻みで3本・2刻みで9本になる)
- [実装判断] X軸の範囲(`xDomainMs`)は `ticks.ts` に純粋関数として切り出した。1か月/半年/1年は `rangeStart(range, today)`〜today、全期間は最古の記録日〜today(最古が14日以内なら today-14日を開始日にする)
- [実装判断] 平均線は燃費・円/L・円/km のどのグラフでも、期間内の値(2点以上のとき)の単純平均を `MetricLineChart` 内で計算して描く。`PeriodStats` には `avgKmPerL` しか無いため、円/L・円/km の平均は `chartSeries.ts` の `average()`(単純平均を取るだけの集計関数)で別途計算する
- [実装判断] 点の半径(`dotRadius`)は「期間内の全行数」ではなく「実際に点が描かれる行数」(=値が非nullの行数)を基準にする。部分給油などで値がnullの行は元々点を描かないため
- [実装判断] 燃費カード右上の「最新」は値に単位を付けない(見出しに既に km/L があるため)。ラベル「最新」→値(大きく)→日付(小さく muted)の順に縦に並べる
- [実装判断] 期間合計行の3桁区切り表示のため `numberFormat.ts` に `formatKmGrouped` / `formatLitersGrouped` を追加した。`src/core/format.ts` の `formatKm` / `formatLiters`(丸め・末尾0省略はするが桁区切りはしない)の出力に、桁区切りだけを足す薄いラッパー
- [実装判断] 選択期間に1件も記録が無い場合(データ自体は存在する)、燃費・コストどちらのグラフ領域も「この期間の記録はありません」を優先して出す(コスト側の「金額の記録がありません」はこの場合出さない)。統計4タイルと期間合計行はすべて `—` にする(合計が0の場合と区別するため)
- [実装判断] `useLiveQuery` の初回読み込み中(戻り値が `undefined`)は見出しのみ表示し、空状態(0件)のちらつきを避ける
- [実装判断] コストグラフの `aria-label` にも燃費側と同様に期間内件数・平均を含める(`PeriodStats` に円/L・円/kmの平均が無いため `chartSeries.average()` で `ChartTab` 側で計算し、平均線の表示条件「2点より多い」と揃えた)
- [実装判断] X軸は目盛線(tickLine)を出さず軸線だけ残す。Y軸は要件通り軸線・目盛線とも出さない(幅36px)

### 画面（記録・一覧・設定、`src/features/record/` / `src/features/list/`）

- [実装判断] `FillupForm` の算出燃費プレビューは `validateFillupForm(values, today)` がフォーム全体として `ok` を返したときだけ出す(走行距離・給油量だけでなく日付・金額も含めて検証する)。要件の「validateFillupFormの結果がokならその値、ダメなら出さない、でよい」に従った

### 監督者（Claude Fable）による実機想定の調整

iPhone 幅（375×812）で全画面を実際に操作して決めたもの。

- [実装判断] 記録フォームは縦に短く組む: 日付はラベルと同じ1行（既定値のまま使うことが多いため）、走行距離と給油量は2列、金額は1行。「詳細」の開閉（左）と算出燃費プレビュー（右）は同じ1行に置く。目的は、テンキーを開いたままでも保存ボタンが隠れず、保存後の結果カードが下部タブバーの裏に回らないこと（要件 §6 の「5操作以内」を、キーボードを閉じる・スクロールする操作なしで満たす）
- [実装判断] 「詳細」は `<details>` ではなく `aria-expanded` 付きのボタン＋領域にした（プレビューと同じ行に置くため）
- [実装判断] 新規入力で日付を手で変えていない間は、日付が変わったら入力欄の日付を今日に追従させる（ホーム画面PWAは何日もメモリに残るため、古い日付のまま保存する事故を防ぐ）。「今日」は `useToday()` が `visibilitychange` / `focus` で更新する
- [実装判断] 「保存しました」の結果カードは、次の入力を始めた時点で消す（次回開いたときに前回の結果が残って紛らわしくならないように）
- [実装判断] 編集シートは App 直下に1つだけ置き、記録タブの直近3件から開いたときも記録タブに留まる（要件「タップで S3 の編集へ」の「S3 の編集」＝編集モーダルと解釈）。「この記録を削除」は区切り線と余白で主ボタンから離す（押し間違い防止）
- [実装判断] 一覧は最初に30件だけ出し、「さらに 30 件を表示（残り n 件）」で増やす。データ管理（設定）は要件どおり一覧タブの最下部に置くので、件数が増えても辿り着けるようにするため（点の間引き禁止はグラフの話で、一覧の段階表示とは別）
- [実装判断] データ管理は「書き出し／取り込み／削除」の3群に見出しを付けて並べる。取り込みは「追記」（CSV）と「置換」（バックアップ）をボタン名に明記
- [実装判断] タブを切り替えたらページ先頭へスクロールを戻す（前のタブのスクロール位置を引き継がない）
- [実装判断] 平均線のラベルは「破線のキー＋平均 14.1」を**プロット領域の外側**（上の余白の右端）に固定する。線の脇やプロット領域の内側に置くと、データの点や線と重なって読めなくなる場合がある（Y軸の余裕はデータ単位、ラベルの高さは px 固定なので、内側では重ならない保証ができない）。平均線そのものはデータの線より下の層に描く
- [実装判断] Recharts の `accessibilityLayer` は無効にした（タップでグラフ全体に白いフォーカス枠が出るため）。代わりにグラフは `role="img"` と要約の `aria-label` を持ち、値の一覧は一覧タブが担う
- [実装判断] グラフタブ（Recharts）は `React.lazy` で別チャンクにし、起動直後の記録タブを軽くする（初期JS 約350KB＋グラフ 約370KB）。チャンクは Service Worker の事前キャッシュに含まれるのでオフラインでも開ける
- [実装判断] ホーム画面PWA（`black-translucent`）ではステータスバーの下まで描画されるため、本文の上余白に `env(safe-area-inset-top)` を足す
- [実装判断] アイコンは全面塗り（角丸・透過なし）。iOS も maskable も OS 側でマスクするため、透過の角があると黒く出る
- [実装判断] 確認ダイアログは編集シートの上に重ねて開くので、Esc は最前面の確認ダイアログだけを閉じる（capture で受けて伝播を止める）。トーストは全レイヤーの最前面
- [実装判断] ナビゲーションのコンテキスト（`useAppNav`）は `src/app/nav.ts` に置く（App.tsx ⇄ 各タブの循環 import を避ける）

### 独立レビュー（Claude Opus）の指摘への対応

実装に関わっていないモデルに不具合探しだけを依頼した結果。データ喪失・誤計算につながる指摘は無し（復元の失敗時ロールバック、CSV/バックアップの異常系、部分給油の連鎖、端末タイムゾーン非依存の日付を実際に壊して確認済み）。

- [実装判断] `saveTextFile` は、iOS で共有シートを使えず `<a download>` を試みた場合に `'unconfirmed'` を返す。呼び出し側は「書き出しました」と言い切らず「保存されたか『ファイル』アプリで確認してください」と出す（バックアップが取れていないのに取れたと誤認させない）
- [実装判断] `parseBackup` は `id` の上限（`Number.MAX_SAFE_INTEGER`）と `exportedAt` が日時として読めることも検証する（巨大な id を復元すると IndexedDB の採番器が壊れて以後の保存が失敗し続ける／`exportedAt` が壊れていると確認メッセージを作れず復元できない）
- [実装判断] 期間内の記録が部分給油だけのとき、燃費グラフは空の軸を描かず「この期間は部分給油だけのため、燃費はまだ算出されていません」と出す
- [実装判断] 記録タブは他のタブを見ている間も隠すだけでアンマウントしない（グラフや一覧を見て戻っても入力途中の値が残る）
- 見送り: `registerType: 'autoUpdate'` は新しい版の配置直後の起動時に自動リロードが走り得る（入力中なら消える）が、全体方針 §2 の固定事項なので変更しない。UI 層（フォーム・データ管理・グラフの分岐）の自動テストは無い（要件の必須範囲は純粋関数。追加するなら jsdom と Testing Library の依存が要る）
